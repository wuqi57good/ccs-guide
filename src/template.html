目前仍不完整的地方

  • 还不是你的板卡实录。官方原图能帮助认窗口，但没有在你的具体 SoC、SDK、CCS 小版本和七个工程上录制操作；截图中的目标和参数会与实际不同。
  • GNU AArch64 专用属性图仍有缺口。可以核对 -I、-D、-O、-g、-T、map 等参数，却不能用别的编译器页面替代所有 GNU 插件的叶子设置。缺图或入口未确认的地方会明确说明。
  • 硬件闭环尚未实测。XDS200 连接、DDR 初始化、缓存一致性、运行中刷新、Profile Clock 与烧录流程，仍要在具体目标上验证。
  • 不是所有小版本的逐项对照。主线图据 CCS 20.5.1 官方手册；旧版补充图据 CCS 12.8。手册沿用的截图可能显示更早构建号，图注会区分来源版本与画面内容。

优先扩展的四个方向

  1. 做一份你的工程实录：确定完整 CCS 版本、SoC/板卡与 SDK，逐屏补齐 Application 及依赖工程的设置和成功日志。
  2. 录制连接到 main 的完整过程：.ccxml → 初始化 → 连接指定 A53 核 → Load ELF → 断点单步，保存每一步的真实状态。
  3. 补一套可运行的小实验：缺头文件、缺库、段溢出、宏分支、Graph 已知数组、.su 栈检查，配“故障 → 修复 → 验证”文件。
  4. 做板级调试专题：按该 SoC 文档补启动链、异常级、MMU/缓存、外部存储烧录与经验证的计时方式。

本页的“自检勾选”由你记录学习结果；浏览器功能测试通过，不代表真实硬件调试已经验收。

核对依据与适用边界

内容核对日期：2026 年 11 月 7 日。以 TI 的 CCS 20.x / CCS 12.x 官方手册为界面依据，GNU 文档为编译与链接依据。20.x+ 代表界面家族，不保证未来版本菜单完全不变；已确认的小版本差异在正文中单独注明。

看到「待核对」时，怎么继续？

先在 Help → About 中记录完整版本号；在目标视图的菜单、工具提示和 Keyboard Shortcuts 中查命令名。硬件相关能力还要对照具体 SoC 的 TRM（技术参考手册）、SDK 及实际连接后的可用按钮。不要用另一个芯片的视频代替确认。

手册内容、交互与进度保存均可离线使用。以下官方参考链接仅在你主动打开时需要联网。示例地址、数值和波形均用于教学，不是你的板卡测量结果。
